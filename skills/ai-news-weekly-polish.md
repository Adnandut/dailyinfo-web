When: the user wants the AI-news weekly recap improved — triggers "润色AI周报", "polish weekly recap", "improve weekly ai news", "优化周报".
---
Take the first-pass weekly recap (generated by the weekly_draft tool) and iteratively improve it through audit → research → rewrite loops, then post it to the Discord channel.

## Contract
- This skill only reads and rewrites the existing draft — it never regenerates the draft content from scratch. If no draft exists, call weekly_draft first (tell the user you are generating it).
- Supplementary research uses web_search.
- The polished article is written with long_write (target filename: the draft's name with `_polished` before `.md`).
- Keep the five-part structure (导读 + 🧠 模型进展 + 🤖 Agent/产品进展 + 🔬 AI for Science + 🏭 产业新闻) but improve depth, accuracy, and readability.
- The article MUST end with the 信息来源 footer (exact format in Phase 3).
- Maximum 3 rewrite loops.

## Quality gates (audit dimensions, score each 1-5)

| # | Dimension | What to check |
|---|-----------|--------------|
| 1 | 导读 hook | Concrete number/finding/contradiction first — not "本周AI领域发生了…" |
| 2 | 模型进展 depth | Cross-day evolution shown? Key methods/numbers included? |
| 3 | Agent/产品 depth | Same as above |
| 4 | AI for Science | If thin but events exist in the draft's source days, flag it |
| 5 | 产业新闻 depth | Business/geopolitical context adequate? |
| 6 | Entity context | Obscure companies/labs/funds get a brief parenthetical (who, what they do) |
| 7 | AI 套话 | Zero banned patterns (blacklist below) |
| 8 | 日期脱敏 | No "X月X日，XX发布了…" treating push date as event date; use 本周初/周中/本周后期; version numbers (GPT-6.2) are NOT dates |
| 9 | 术语密度 | ≤3 proper nouns per paragraph, BUT protagonist names and model version numbers are facts, not decoration — never replace "GPT-6.2" with "新一代旗舰模型"; trim investor lists and comparison-benchmark name-dumps |
| 10 | 主线聚焦 | Per section: 1-2 developed storylines (150-300 字 each), rest one line or cut; 国产 AI 突破 (DeepSeek/智谱/Qwen/美团/Kimi) deserve more space for Chinese readers |
| 11 | 递进克制 | No "随后/紧接着/与此同时" without a real causal/temporal link; independent events stand alone |
| 12 | 数字密度 | ≥5 specific numbers, each with context explaining why it matters |

AI 套话黑名单 (never appear): 值得注意的是 / 值得一提的是 / 此外 / 综上所述 / 总而言之 / 整体来看 / 本周AI领域发生了许多重要事件 / 让我们拭目以待 / 值得持续关注 / 不可否认 / 毫无疑问 / 显然 / 与此同时 (无真实并发关系时)。

## Phase 0 — Locate the draft
Call read_weekly_draft (no argument = latest). If it reports none, call weekly_draft first (tell the user). Read the draft fully; note date, length, structure.

## Phase 1 — Quality audit (self-audit, single-pass mode)
Score ALL 12 dimensions against the draft. Output an internal table with specific quoted phrases as evidence. Identify every weakness — do not fix yet. Keep the audit for Phase 4 comparison.

## Phase 2 — Supplementary research
For each gap: web_search for (a) obscure entities without context, (b) thin cross-day events, (c) missing numbers behind vague claims ("表现优异" → find the score), (d) fact-check superlatives ("首个"/"最大"/"革命性"), (e) event-date verification when the draft anchors a claim to a specific day. Collect findings as bullets under each gap. Do NOT rewrite yet.

## Phase 3 — Rewrite
Call long_write with the draft's filename (`_polished` before `.md`). Before calling, compose internally: apply every Phase-2 finding; select 1-2 主线故事 per section (cross-day evolution and specific numbers win; 国产 AI 突破优先); demote the rest to one line or cut; apply 日期脱敏, 术语密度, 递进克制; long-short sentence rhythm; numbers with reference points ("78% —— 距离实用门槛 ~85% 只差临门一脚"); replace weak transitions with real connections or paragraph breaks. AI for Science genuinely empty → write "本周暂无重要进展。" — don't pad.

End the article with exactly:

```
---
> 📮 **信息来源**：本文基于 dailyinfo 每日 AI News 简报生成，原始新闻来自 [Latent Space](https://www.latent.space/) 的 AINews 日报。关键事件细节经 web_search 交叉验证。数据截至本周日。
```

## Phase 4 — Re-audit
Re-score the polished article on all 12 dimensions (compare against Phase 1). Exit when: all ≥3, at least 3 dimensions improved by ≥1, and dimensions 8-11 average ≥3.5. If not met: research the remaining gaps (web_search) and rewrite only the affected sections with long_write. Max 3 loops; if still failing, tell the user the remaining gaps honestly.

## Phase 5 — Publish + report
Call post_article (default channel: ai-news) to post the polished article in parts. Then give the user a short report: what improved, loop count, research queries used, remaining gaps if any.
