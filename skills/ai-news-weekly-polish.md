Take the first-pass weekly recap (generated by the weekly_draft tool) and iteratively improve it through audit → research → rewrite loops, then post it to the Discord channel. The article is written in ENGLISH.

## Contract
- This skill only reads and rewrites the existing draft — it never regenerates the draft content from scratch. If no draft exists, call weekly_draft first (tell the user you are generating it).
- Supplementary research uses web_search.
- The polished article is written with long_write (target filename: the draft's name with `_polished` before `.md`).
- Keep the five-part structure (TL;DR + 🧠 Model Progress + 🤖 Agents & Products + 🔬 AI for Science + 🏭 Industry News) but improve depth, accuracy, and readability.
- The article MUST end with the Sources footer (exact format in Phase 3).
- Maximum 3 rewrite loops.

## Quality gates (audit dimensions, score each 1-5)

| # | Dimension | What to check |
|---|-----------|--------------|
| 1 | TL;DR hook | Opens with a concrete number, finding, or contradiction — not "This week saw many important AI developments" |
| 2 | Model Progress depth | Cross-day evolution shown? Key methods/numbers included? |
| 3 | Agents & Products depth | Same as above |
| 4 | AI for Science | If thin but events exist in the draft's source days, flag it |
| 5 | Industry News depth | Business/geopolitical context adequate? |
| 6 | Entity context | Obscure companies/labs/funds get a brief parenthetical (who they are, what they do) |
| 7 | Filler patterns | Zero banned phrases (blacklist below) |
| 8 | Date de-sensitization | No "On Nov 19, X released…" treating the push date as the event date — the briefing date is when news was COLLECTED. Use "early this week / midweek / later in the week". Version numbers (GPT-6.2) are NOT dates — keep them |
| 9 | Term density | ≤3 proper nouns per paragraph, BUT protagonist names and model version numbers are facts, not decoration — never replace "GPT-6.2" with "the new flagship model". Trim investor lists and comparison-benchmark name-dumps. A description ADDS to a name ("Baseten (enterprise inference hosting platform)") — it never REPLACES it |
| 10 | Storyline focus | Per section: 1-2 developed storylines (150-300 words each), the rest one line or cut. Breakthroughs from Chinese labs (DeepSeek, Zhipu/GLM, Qwen, Meituan, Kimi) deserve full detail — they are hardest to follow from English channels. "Fewer, deeper" beats "more, shallower" |
| 11 | Transition restraint | No "then / immediately after / meanwhile / following this" without a real causal or temporal link; independent events stand alone as paragraphs |
| 12 | Number density | ≥5 specific numbers, each with context explaining why it matters ("78% accuracy — just short of the ~85% usability threshold") |

Filler blacklist (never appear): "It is worth noting that" / "Notably," (as filler) / "In addition" (as padding) / "In summary" / "All in all" / "Overall," / "This week was an active week for AI" / "Let's wait and see" / "Worth watching" / "Undeniably" / "Without a doubt" / "Obviously" / "Meanwhile" (without real concurrency) / "not only … but also …" (as decoration).

## Phase 0 — Locate the draft
Call read_weekly_draft (no argument = latest). If it reports none, call weekly_draft first (tell the user). Read the draft fully; note date, length, structure.

## Phase 1 — Quality audit (self-audit, single-pass mode)
Score ALL 12 dimensions against the draft. Output an internal table with specific quoted phrases as evidence. Identify every weakness — do not fix yet. Keep the audit for Phase 4 comparison.

## Phase 2 — Supplementary research
For each gap: web_search for (a) obscure entities without context, (b) thin cross-day events, (c) missing numbers behind vague claims ("performs well" → find the score), (d) fact-check superlatives ("first ever" / "largest" / "revolutionary"), (e) event-date verification when the draft anchors a claim to a specific day. Collect findings as bullets under each gap. Do NOT rewrite yet.

## Phase 3 — Rewrite
Call long_write with the draft's filename (`_polished` before `.md`). Before calling, compose internally: apply every Phase-2 finding; select 1-2 main storylines per section (cross-day evolution and specific numbers win); demote the rest to one line or cut; apply date de-sensitization, term density, and transition restraint; alternate long and short sentences; give numbers reference points ("78% — just short of the ~85% usability threshold"); replace weak transitions with real connections or paragraph breaks. AI for Science genuinely empty → write "No significant developments this week." — don't pad.

End the article with exactly:

```
---
> 📮 **Sources**: This article is generated from the dailyinfo daily AI-news briefings; original news from [Latent Space](https://www.latent.space/) AINews. Key events cross-checked via web_search. Data as of Sunday.
```

## Phase 4 — Re-audit
Re-score the polished article on all 12 dimensions (compare against Phase 1). Exit when: all ≥3, at least 3 dimensions improved by ≥1, and dimensions 8-11 average ≥3.5. If not met: research the remaining gaps (web_search) and rewrite only the affected sections with long_write. Max 3 loops; if still failing, tell the user the remaining gaps honestly.

## Phase 5 — Publish + report
Call post_article (default channel: ai-news) to post the polished article in parts. Then give the user a short report: what improved, loop count, research queries used, remaining gaps if any.
